# Rising Tide 003B — fixed protocol

November 4, 2026, America/Phoenix. The fixtures, query lengths, repair threshold, and correctness checks were fixed before the pilot measurements. The bookkeeping and direct-query improvements made after that pilot are disclosed below.

Purpose: audit the supplied Rising Tide 003 claim and run its changing-graph follow-up. This is a new experiment, not the original executable packet. The original graph and fourteen lengths were recovered from HANDOFF.md, version 2, Library ID [private-library-ref]. Its code was not recovered; the original mathematical construction is independently reimplemented.

1. Reproduce 128 matrix comparisons for lengths 0–127 and the original operation-count convention; add ordinary fresh binary exponentiation and remove avoidable identity multiplications in a separate comparison.
2. Check six strict frontier transitions in a corrected, explicitly restricted full-matrix expression model. This is not a lower bound for single-pair decision algorithms.
3. Maintain P_j = A^(2^j) for j=0,...,7. For each square retain integer supports S_j[i,k] = sum_v P_j[i,v] P_j[v,k]. These count possible midpoint vertices, not complete walks.
4. For an edit, propagate the exact Boolean changes through the levels. Repair a square by sequential cell updates when 8d <= q^2; otherwise recompute the entire square with support counts. Stop propagation when a level's Boolean matrix does not change. Count selection work and failed usefulness, with no tuning of the threshold after seeing results.
5. Compare complete rebuilding on every graph version, fresh binary exponentiation per query, and retained repair. All three answer single-pair queries with row selection and vector–matrix products. None retrieves earlier complete answers.
6. Charge initial acquisition, graph/edit validation under a known-parent delta interface, routing, input bit tests, table lookup, arithmetic/data updates, and independent per-answer checking. Count work events in the explicit categories in the code. This is an abstract ledger, not CPU-instruction counting. Python allocation, garbage collection, cache behavior, and the cost of inventing this algorithm are not represented.
7. The per-answer checker starts from the raw current graph and advances vertex sets one step at a time. It checks both yes and no answers. The same cost is paid separately by every method. An additional research audit independently rebuilds every retained power and checks every support entry; report its entry count separately, not as online service work.
8. Use four predetermined workload families: disconnected cycles, redundant dense graph, looped bridge with quadratically many changed reachability entries, and random sparse graph with seed 20261104. The first three have eight toggles of one edge; the random family has twelve predetermined toggles. Each version has thirteen different lengths up to 255 and varied endpoints.
9. Include a negative control with the bridge graph, the same configured horizon, and only a length-one query per version. This deliberately tests the cost of maintaining capabilities the workload does not use.
10. Exhaustively test all 512 directed graphs on three vertices (self-loops allowed), each of nine edge toggles, through powers of length 16. Force the sparse update formula here so dense fallback cannot conceal a sparse-update defect. Compare all Boolean matrices and midpoint counts with independently constructed references. Reject deliberately wrong answers.

Correctness invariants and exclusions: Exact-length walks are not unrestricted transitive closure; self-loops are only present when specified in a fixture. Integer support counts lie in [0,q]. The parent version is supplied, not discovered. Research audit checks are reported separately from online verification. No universal speedup, novel algorithm discovery, indefinite frontier growth, or P-versus-NP result is claimed.

## Measurement revision after pilot

The pilot code and results are preserved under development/. The final version replaces an estimated sorting allowance with a deterministic, fully charged q^2 scan of candidate output coordinates. It also removes the fresh solver's unnecessary copy of the current graph and answers single-power pair queries by direct entry lookup in every applicable method. These changes improve the fresh comparator and make the ledger easier to interpret. The graph fixtures, edit streams, query lengths, and sparse/dense threshold did not change. Final claims refer only to results.json, whose code hash identifies the final experiment.py. The complete correctness suite was rerun after these edits.
